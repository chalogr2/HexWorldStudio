# CLAUDE.md — orientation for future Claude Code sessions

You are reading this because you are continuing development on **Hex World Studio**, a Unity Asset Store product. Read this file first, then check [`FEATURES.md`](FEATURES.md), [`DECISIONS.md`](DECISIONS.md), and (when it exists) `ARCHITECTURE.md`. Only then begin work.

## What we're building

A **procedural hex world generator for Unity** — a code-first asset that generates believable, Civ-style hex maps (continents, biomes, rivers, resources, starting positions) for indie devs making 4X, turn-based strategy, or hex-grid games.

- Provisional product name: **Hex World Studio** (not finalized).
- Target sale price: **$39.99**, launching at **$29.99** with the Asset Store new-release discount.
- Scope is *only* world generation + data layer + custom editor + clean runtime API. It is **not** a combat framework, **not** a city builder, **not** a full 4X engine.

## Architectural principles

1. **Data and rendering are completely separate.** The generator produces a pure-data `WorldMap`. A separate visualization layer renders it. Buyers must be able to use the data without our renderer and swap our renderer without touching our data.
2. **ScriptableObject-driven content.** Biomes, resources, tile features, and world presets are ScriptableObjects. Buyers add content from the inspector, not by editing code.
3. **Deterministic generation.** Same seed + same settings = byte-identical output. Always. Critical for multiplayer, daily challenges, reproducibility.
4. **Public API stable; internals can change.** Public-facing types get XML doc comments. Everything else is `internal` by default so we can refactor without breaking buyers.
5. **No magic.** No reflection-based wiring, no unmarked side effects, no clever metaprogramming. Any file should be understandable in 60 seconds.
6. **Tests over hopes.** Critical pipeline stages and determinism get unit tests via Unity Test Framework.

## Documentation discipline (mandatory)

Four files in the repo root, maintained in lockstep with the code:

- [`CLAUDE.md`](CLAUDE.md) — this file. Update whenever project state meaningfully changes.
- [`FEATURES.md`](FEATURES.md) — living inventory. **Add features here before implementing them.** Status legend: `[ ] planned`, `[~] in progress`, `[x] done`, `[!] blocked`, `[-] descoped`.
- [`DECISIONS.md`](DECISIONS.md) — architectural decision log. Add an entry whenever a meaningful choice is made (date, decision, alternatives, reasoning).
- [`ARCHITECTURE.md`](ARCHITECTURE.md) — subsystem layout, pipeline order, code-layout map. Update whenever a subsystem's shape or contract changes.

**Hard rule: docs update in the same commit set as the work that triggered them.** If a prompt or exchange produces code, an ADR-worthy decision, a workflow change, or a clarification that future sessions will need to know about, the relevant docs are updated in the same set of commits as the code. No "I'll update docs later" — later is now. This applies equally to ADR additions, FEATURES status flips, ARCHITECTURE notes, and CLAUDE.md project-state refreshes.

Plus: XML doc comments on every public type and member from the moment it's created.

## Workflow rules

- **Propose before implementing.** Output a design document and wait for confirmation before writing code. Same for major changes.
- **Chain slices within a session.** Sessions are expected to span the rest of v1 development, not one slice per session (see ADR-0008). The propose-before-implementing gate is preserved per slice — each slice still gets a written proposal and an explicit approval before code lands — but completing one slice does not end the session. Move on to the next slice unless the user explicitly asks for a hard break.
- **Small commits, Conventional Commits format** (`feat:`, `fix:`, `docs:`, `refactor:`, `test:`, `chore:`). One logical change per commit. The git log should read like a changelog.
- **No code without a place to put it.** Propose folder layout first.
- **Stop and ask** on ambiguity, principle conflicts, or scope expansion.
- **No new dependencies** (Unity packages, NuGet, npm, anything) without explicit approval.

- **Slice 12** (biome + feature cohesion smoothing, ADR-0019): two new pipeline stages address the single-tile speckling visible at biome boundaries (especially deserts looking dotted instead of contiguous). `BiomeCohesionStage` runs right after `BiomeAssignmentStage`; `FeatureCohesionStage` runs right after `TileFeaturePlacementStage`. Each stage reads a 0..1 strength slider on `WorldGenerationSettings` (`BiomeCohesion`, `FeatureCohesion`), maps it via the public `BiomeCohesionStage.FromStrength` to `(iterations, threshold)`, and runs an order-independent (double-buffered) neighbor-consensus pass: for each non-water tile, count same-type neighbors; if fewer than threshold do, switch to the most-common neighbor (ties broken by `Biomes` order for biomes, by `AllowedFeatures` order for features — both deterministic). Strength 0 is a complete no-op. Water tiles preserved (topology-classified). Feature smoothing's candidate set is restricted to the tile's biome's `AllowedFeatures` so cohesion can never violate biome-feature compatibility. Defaults: 0.5 (biomes — mild Civ-like blobs) and 0.3 (features — preserve natural diversity). `WorldGeneratorBootstrap` surfaces both as `[Range(0, 1)]` sliders under a new "Cohesion" header. New 7-arg `WorldGenerationSettings` ctor is the primary; the legacy 5-arg ctor delegates to it with default cohesion values so existing call sites compile unchanged.
- **Slice 13** (pluggable continent-shape algorithms, ADR-0020): `ContinentShapeStage` becomes a thin router that dispatches on the new public enum `WorldGenerationSettings.ContinentShapeAlgorithm` (default `Continents`). Seven shipped algorithms live in `ContinentShapeAlgorithms` (one static method each, single switch dispatch): `Continents` (default — historical Slice-5 Perlin percentile), `Pangaea` (lower-frequency Perlin + mid-row Gaussian boost), `Archipelago` (high-frequency 2-octave fBm), `Fractal` (6-octave fBm — irregular coastlines), `InlandSea` (Perlin minus a mid-row Gaussian — land ring), `Lakes` (highest-frequency fBm, expects high `LandRatio`), `Shuffle` (RNG-picks one of the others via `"continent-shape-shuffle"` label). Every algorithm forks the master RNG with a distinct label so the seeded stream for any one algorithm is invariant to others being added or reordered — most importantly Continents keeps `"noise-continent-shape"` so all existing buyer-pinned Continents seeds remain byte-identical. Every algorithm finishes via the shared percentile-threshold helper so `LandRatio` is honored within ±2 tiles regardless of bias gradients. Shuffle draws from an explicit hardcoded pool (`s_ShufflePool`) rather than enum iteration so appending new algorithm values later does not shift existing-seed Shuffle worlds. `WorldGenerationSettings` gets an 8-arg primary constructor with the algorithm slot; the 7-arg cohesion constructor delegates with `DefaultContinentShape = Continents` so existing call sites compile unchanged. `WorldGeneratorBootstrap` surfaces the choice as an inspector enum field next to the biome roster. - **Slice 16** (resource render modes — surface placement + replace-tile, ADR-0023): two follow-ups to Slice 15. - **Slice 16.1** (deterministic per-coord resource rotation): every resource visual — both replacement prefabs in replace-tile mode and add-on-top prefabs in default mode — gets a Y rotation snapped to one of the six hex sextants (`{0, 60, 120, 180, 240, 300}` degrees). `WorldRenderer.GetResourceRotationY(coord)` is a pure function of `(coord.Q, coord.R)` via a Wang-style integer hash mod 6, so re-renders never produce visual jitter, the same world is bit-stable across machines, and no RNG fork is involved in the render path. 60° steps preserve hex-grid alignment — every rotation still maps the prefab to a valid hex side. +3 EditMode tests cover the snap-to-60 invariant over a 21×21 coord sample, the determinism contract (same coord → same rotation), and the variation contract (adjacent coords typically produce different rotations).
- **Slice 17** (edge-based rivers, ADR-0024): tenth pipeline stage `RiverStage` runs after `ResourcePlacementStage`. Forks RNG with `"river-generation"` label. Source selection: land tiles with `ElevationLevel ≥ RiverSourceMinElevation` (default 4 of 6); per-tile source probability is `RiverDensity × tile.Moisture` (default RiverDensity 0.15 — Civ-style; moisture weighting means dry areas get fewer rivers). Downhill walk: strict-lower elevation neighbor with RNG tie-break, edges recorded as canonical `RiverEdge` (public struct at `Runtime/Data/RiverEdge.cs`; lex-smaller endpoint owns the naming, `Canonicalize(owner, dir, mapWidth)` handles cylindrical wrap). Termination on water reach / merge with existing edge / `MaxRiverLength` safety cap / local minimum → tile flips to Coast lake biome. Opt-out via `RiverDensity = 0`. `WorldMap.RiverEdges` is public `IReadOnlyList<RiverEdge>` sorted deterministically; `WorldMap.HasRiverAt(coord, dir)` and `WorldMap.CountRiverEdgesAround(coord)` are the buyer query surface (canonicalize inputs internally, direction-agnostic). New `Runtime/Content/RiverStyleAsset.cs` SO carries Material + WidthRelativeToHex + SurfaceYOffset + BaseColor. New `Runtime/Rendering/RiverRenderer.cs` MonoBehaviour reads `RiverEdges` and emits one procedural quad per edge into a single shared Mesh under a `"Rivers"` child GameObject; quad Y = `max(landY_A, landY_B) + SurfaceYOffset` from `WorldRenderer.ComputeTileY`; UVs follow standard `U-across-V-along-flow` so any URP water material scrolls flow via `_Time.y * _FlowSpeed`. `RiversRebuilt` event lets advanced buyers ignore the default renderer and draw their own. Cylindrical wrap works transparently — the wrap renderer clones the Rivers child alongside tiles. - **Slice 17.3** (corner-network rivers, ADR-0025 — supersedes the generation and rendering halves of ADR-0024): rivers are now **paths through hex corners** rather than sets of edges repaired after the fact. New public `HexCorner` (`Runtime/Data/`) is the canonical hex-vertex identity — three hexes meet at a corner, every corner has three neighbours, and a step between adjacent corners traverses exactly one hex edge, so chains are corner-connected by construction. `AddCornerConnectors` is deleted, not fixed. New internal `Runtime/Generation/Hydrology/DepressionFill.cs` (priority flood, hand-rolled min-heap since Unity's netstandard2.1 runtime predates `PriorityQueue`) removes the pits raw fBm is full of, raising to just *above* the spill level so filled basins are not perfectly flat. Lakes are derived from the filled basins before any walking (`HexTile.IsLake`), so they are contiguous and rivers terminate at them naturally. `RiverStage` walks a constrained corner graph with depth-first backtracking: an edge must have land on both sides; the destination corner must be strictly lower on the filled field; the edge is either a **channel** between two tiles of equal `ElevationLevel` or a single-edge **waterfall** crossing a terrace boundary (bounded by `MaxWaterfallDrop`, never two in a row); and terrace levels stay continuous along the path. The walk stops the instant it reaches a corner touching water, which is what ends coastline-hugging. New public `RiverStep` / `RiverPath` and `WorldMap.RiverPaths` give the ordered, directed view with Strahler order; `RiverEdges` keeps its exact ADR-0024 contract. `RiverRenderer` rewritten as one mitered ribbon per path (no caps, terrace-aligned height, monotone `V`, Strahler width taper, lip/face/plunge waterfalls); `HexMesh.CornerPosition` is the new shared corner-geometry helper; `WorldRenderer.ComputeTileY` puts lakes at their terrace height; `WorldWrapRenderer` takes an explicit `RiverRenderer` reference instead of relying on shared-GameObject luck. Three new settings (`MinRiverLength` 3, `MaxWaterfallDrop` 1, `LakeDepthThreshold` 0.08) via a 16-arg primary ctor; the 13-arg ctor delegates. **Two defaults retuned on measured evidence**: `RiverSourceMinElevation` 4 → 3 (its meaning changed from one source tile to the lowest of a corner's three tiles; at 4 only ~6% of land corners qualified and maps averaged 1.5 rivers, at 3 they average 8.8 rivers over 60 edges with confluences forming) and `LakeDepthThreshold` 0.02 → 0.08 (~21 three-tile lake bodies per map reads as speckle; ~3.5 four-tile bodies reads as water). +40 EditMode tests across `HexCornerTests`, `DepressionFillTests`, `RiverStageTests` (rewritten), and `RiverRenderGeometryTests`.
- **Verification tooling note (Slice 17.3):** the Unity editor cannot run headless while it is open, so the Coordinates / Data / Content / Generation layers were compiled and executed standalone against a small `UnityEngine` shim (only `ScriptableObject`, `GameObject`, `Material`, `Color`, `Mathf`, `Vector2/3`, `Mesh`, and a few attributes are needed — those folders touch nothing else). The harness compiles the **real source files in place** rather than copies, so it cannot drift from what Unity builds. It caught two bugs that reading did not: a namespace error in `HexCorner`, and the river walk silently discarding every river that failed to reach the sea. Worth rebuilding whenever generation logic changes; `Rendering/` and `Input/` stay out of scope because they need the component system.
